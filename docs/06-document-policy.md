# 文件政策

## 目的

讓 AI agent 能從小型 index 逐層取得必要脈絡，避免每次都讀取整個專案歷史。日常任務先讀 `docs/index.md` 與相關主題；只有追溯決策時才讀 `changelog.md`。

## 單檔限制

每份規格文件上限 3000 字元（以 UTF-8 字元數計算，工具與 CI 使用同一規則）。文件應優先保留：目的、不可違反的 policy、介面契約、驗收條件。範例、背景與歷史細節放到獨立文件或 changelog。

## 自動整理流程

文件檢查由 `scripts/check-docs.sh` 與 CI 自動執行。發現超限時，CI 只負責阻止合併並指出檔案；內容整理仍必須依下列流程進行，不自動刪除原文：

1. 找出超限文件與超出數量。
2. 保留標題、結論、policy、必要連結與 `最後更新`。
3. 將可延後查詢的細節拆至有語意名稱的新文件。
4. 產生短摘要或更新既有摘要，並更新 `index.md` 路由。
5. 保留原決策於 `changelog.md`，不得無聲刪除資訊。
6. 重新檢查所有文件；若仍超限，繼續拆分，不以截斷檔案作為完成。

整理器本身需提供 dry-run，預設不覆寫；真正寫入前應顯示變更，並以測試驗證索引連結、字數與資訊保留規則。AI 摘要若失敗，應停止並要求人工整理，不得產生不完整文件。
